# N06 / N07 記録（2026-11-02）

対象は N06（Prefill / Decode の混合スケジューリング）と N07（4 並列時の実効性能）。
計測は gfx1201 の 1 GPU、`build/hip-rel`（Release）、指示が無い限り prefix cache 無効。
prompt 64 token、max_new 32、`--no-eos`、`--prefill-rows 64`、`--max-batch 4`。

## N06: prefill / decode の交互実行

### 問題

従来の `step_once` は prefill を優先していた。長い prefill は 1 チャンク
（`--prefill-rows`、既定 64）ずつ進むが、チャンクの間にも decode を挟まないため、
生成中の要求は prefill が終わるまで止まる。9B-FP8 で 1024 token の prefill を
生成中に投入すると、生成側のトークン間隔が最大 622 ms 空いた。

### 実装

- `apps/shelf_compute.cpp` の `step_once` で、prefill と decode の両方が実行可能な
  ときは **1 ステップずつ交互** に流す（`last_prefill_step_` で前回を覚える）。
  片方しか無いときはそのまま進める。
- `--no-interleave` で従来動作に戻せる（比較・回帰用）。
- チャンク境界は `--prefill-rows` のまま。チャンクを細かくする案より実装が単純で、
  KV / GDN 状態の復元とも干渉しない。

### 測定（9B-FP8、生成中に 1024 token の prefill を後から投入）

| 指標 | 交互なし | 交互あり |
| --- | --- | --- |
| 生成側の最大トークン間隔 | 621.1 ms | **71.2 ms** |
| 生成側の p95 間隔 | 34.6 ms | 58.6 ms |
| 長い prefill の TTFT（投入から最初のトークンまで） | 451.9 ms | **126.4 ms** |

27B-MXFP4 でも同じ傾向で、最大間隔は 1387.8 ms → **180.5 ms**。
（N07 の decode_n 導入後は decode 1 ステップが短くなるので、同じ測定で
9B-FP8 67.3 ms、27B-MXFP4 157.5 ms に改善している。）
prefill のチャンクが decode の合間に入るため生成側の p95 は悪化する（34.6 → 58.6 ms）が、
最大待ちは 8.7 倍改善する。aggregate は変わらない（L1 44.3 → 43.9 tok/s、誤差の範囲）。

### 回帰確認（交互実行を既定にした状態）

- N01 の 1〜4 並列一致: 9B-FP8 4/4（aggregate 47.6 tok/s）、
  27B-MXFP4 4/4（aggregate 16.1 tok/s）。
- N03 の Prefix Cache × 4 並列: 9B-FP8 / 27B-MXFP4 ともすべて一致。

## N07: 4 並列の実効性能

### 測定（decode_n 導入前）

9B-FP8:

| 並列 | aggregate tok/s | TTFT 中央 / p95 | TPOT 中央 / p95 |
| --- | --- | --- | --- |
| 1 | 44.1 | 47.9 / 47.9 ms | 21.8 / 21.8 ms |
| 2 | 55.3 | — | 34.3 / — ms |
| 4 | 64.7 | 145.2 / 263.4 ms | 57.4 / 58.1 ms |

27B-MXFP4:

| 並列 | aggregate tok/s | TPOT 中央 |
| --- | --- | --- |
| 1 | 17.7 | 55.4 ms |
| 2 | 19.7 | 99.1 ms |
| 4 | 21.0 | 184.0 ms |

Prefix Cache を温めた場合（9B-FP8、4 並列、prefix 32 ブロック）は
TTFT 146.8 → 136.0 ms、aggregate 64.8 → 65.0 tok/s。prompt が 64 token と短く、
prefill 自体が小さいため差は TTFT にしか出ない。

### 原因

N01 で rows ≤ 4 を **行ごとの decode1**（GEMV を 4 回）に揃えたため、4 並列でも
重みを 4 回 DRAM から読んでいた。decode は重み帯域律速なので、並列数を増やしても
aggregate がほとんど伸びない（27B で 17.7 → 21.0 tok/s）。

### 改善: 行ごとに波を割り当てる decode_n（2〜4 行）

- `gemv_fp8_w8a8_decode_n_kernel`（`linear_fp8_decode.hip`）と
  `gemv_mxfp4_w4a8_decode_n_kernel`（`linear_mxfp4_decode.hip`）を追加した。
  1 波 = 16 出力は decode1 と同じで、**ブロック内の波に行を割り当てる**。
  4 波が同じ重みアドレスを読むので L2 に載り、DRAM の読み出しは 1 行ぶんになる。
- 行ごとの本文は decode1 と共通（`fp8_decode1_body` / `mxfp4_decode1_body` に
  レーン番号を渡す形へ切り出した）。したがって出力は
  **行ごとに decode1 を呼んだ結果とビット同一**。単体テスト
  `test_hip_gemm_row_parity` の `decode_n` 節が rows = 2, 3, 4 をシェイプ別に
  `memcmp` で確認する（MXFP4 と FP8 の per-channel / block128 の両方）。
- 起動する波は `rows` 本ぶんだけ（rows = 2 で 4 波を出すと半分が遊ぶ）。
- 活性化の量子化は従来どおり 1 行ずつ（`tiled_bytes(1, k_padded)` 間隔で並べる）。

#### カーネル単体（4 行、100 回の平均、µs）

| 形（N × K） | decode1 を 4 回 | decode_n | 差 |
| --- | --- | --- | --- |
| fp8 4096 × 4096 | 57.9 | 26.0 | −55% |
| fp8 12288 × 4096 | 113.9 | 47.3 | −59% |
| fp8 4096 × 12288 | 106.3 | 42.1 | −60% |
| fp8 10240 × 5120 | 112.2 | 52.9 | −53% |
| fp8 17408 × 5120 | 568.7 | 141.2 | −75% |
| fp8 5120 × 17408 | 557.5 | 140.7 | −75% |
| mxfp4 10240 × 5120 | 231.3 | 121.3 | −48% |
| mxfp4 17408 × 5120 | 269.2 | 189.6 | −30% |
| mxfp4 5120 × 17408 | 592.8 | 198.4 | −67% |

（比較用の計測は `/tmp/decoden_bench.cpp`。`decode1` 4 回の合計と `decode_n` 1 回を
hipEvent で測る。最初に書いた「1 波で 4 行を畳む」版は、FP8 の 4096 × 12288 で
+122% と大きく負けた。重みの L2 共有が効かず、1 波あたりの仕事が 4 倍になるだけ
だったため。波を分ける版に変えて全シェイプで勝つようになった。）

| モデル | 並列 | aggregate tok/s | 導入前 | 差 |
| --- | --- | --- | --- | --- |
| 9B-FP8 | 1 | 44.3 | 44.1 | ±0 |

| | 4 | **78.0** | 64.7 | **+21%** |

| | 4 | **32.0** | 21.0 | **+52%** |
| 27B-FP8 | 1 | 18.4 | — | — |
| | 2 | 29.2 | — | — |

TPOT（4 並列、中央値）は 9B-FP8 57.4 → 46.3 ms、27B-MXFP4 184.0 → 115.0 ms、
27B-FP8 179.2 → 85.1 ms。1 並列は decode1 のままなので変わらない。
N01 の 4 並列一致は維持している（4 モデルとも 4/4）。

### 残っている課題

- 4 並列の TTFT p95 が 9B で 253 ms、27B で 509〜557 ms と大きい。4 要求の
  prefill が 1 チャンクにまとまらず直列化するためで、prefill のスロット並列化が
  次の候補。
- decode_n は 4 行まで。`--max-batch` を 4 より大きくするなら波数の上限を上げる。
- MoE（35B-A3B）は expert の CPU 実行が支配的なので、decode_n の効果は線形層の
  ぶんだけになる。N08〜N10 で別に扱う。
