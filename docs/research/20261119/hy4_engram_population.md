# Hy4-flash の Engram 読み込みと固定の検証

この調査は 2026-11-19 に R9700×1 と V620×2 の別構成で行った。R9700×3／×4 の実測ではない。4 bpw 本体と DFly2、FP8 Engram 4 表を使い、server の起動後に 110 token の同一入力を送った。Engram は file-backed mmap で、固定しなければメモリ圧迫時に退避される。

request の profile では、遅延 mmap の初回 decode は Engram 参照が 12,628 ms、23,363 major fault、2 回目は 3.62 ms、0 fault だった。populate のみは読み込み後に全表を同時に維持できず、ready 時の常駐は 9,874,781 / 15,791,171 ページだった。全表 mlock 時は 15,791,171 / 15,791,171 ページで、初回の Engram 参照は 4.06 ms、2 major fault だった。profile は同期と常駐確認を含むため通常速度とは比較しない。

全表の tensor は 64,680,628,768 byte。固定にはページ境界を含む memlock 上限が必要で、測定時の `VmLck` は 63,164,684 KiB だった。読み込み・固定に要した時間はキャッシュ状態により 57.21〜241.94 秒だった。GPU 重み転送も別に必要である。起動時読み込みは major fault を前倒しするが、固定なしでは後の常駐を保証しない。

BetterBench の固定前・固定後の比較は[性能記録](../../perf/current.md#hy4-flash-の-engram-固定に関する別構成の参考測定)に示す。測定では server をカテゴリごとに再起動し、固定後の全表常駐を確認した。異なる nonce と生成列を含むため、速度差を固定の効果だけに帰属できない。固定なし、固定ありの初回と後続 request の両方を実環境で確認する必要がある。
