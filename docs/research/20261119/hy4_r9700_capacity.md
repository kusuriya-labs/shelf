# Hy4-flash の R9700 複数台に向けた容量試算

これは移植前の静的試算であり、R9700 複数台での実予約結果ではない。実装と予約時の空き容量検査が必要である。

4 bpw 本体の `conversion_report.json` は 205,729,506,824 byte と報告する。この値には BF16 Engram が含まれる。移植元の loader は BF16 Engram を GPU に置かず、別途変換した FP8 Engram をホストに置き、必要な行を取得する。FP8 表の tensor は 64,680,628,768 byte であり、別途ホストメモリが必要である。checkpoint の総バイト数をそのまま VRAM の必要量と扱えない。

以下は既存の予約計画に基づく概算である。GPU 常駐の固定重み 4,329,651,680 byte、4 bit expert 20,992 個を各 3,557,376 byte、DFly 固定重み 424,624,962 byte とする。固定重みは移植元で配置済みの重み合計から expert を差し引いた値で、DFly は別途加算する。rank 0 に attention、head、KV、indexer と DFly を置き、作業域は rank 0 に 2 GiB、その他に各 0.5 GiB を仮定する。KV と indexer は移植元のサイズ式を用いる。expert の個数は容量の試算例であり、校正頻度による負荷分散を保証しない。

| 予約長 | GPU 台数 | expert 数の例 | rank ごとの概算 GiB |
|---|---:|---|---|
| 1Mi | 3 | 5000 / 7996 / 7996 | 27.193 / 26.991 / 26.991 |
| 2Mi | 3 | 5000 / 7996 / 7996 | 31.388 / 26.991 / 26.991 |
| 1Mi | 4 | 4000 / 5664 / 5664 / 5664 | 23.880 / 19.265 / 19.265 / 19.265 |
| 2Mi | 4 | 4000 / 5664 / 5664 / 5664 | 28.075 / 19.265 / 19.265 / 19.265 |

2Mi の Octave KV は 7,403,321,016 byte、indexer は 1,610,649,600 byte。表は folded 重み、expert 射影表、アラインメント、実際の空き容量やその他の runtime overhead を含まない。特に 3 台の 2Mi は rank 0 の余裕が小さく、この表だけでは予約可能と判断できない。4 台も同様に実予約が必要である。1 台と 2 台は expert と固定重みだけで 64 GiB を超えるため、この常駐方式では収まらない。

## expert 本数の調整

checkpoint の safetensors header から固定重みと expert の実サイズ、config から folded 重みを集計し、rank ごとの固定使用量を先に加えたうえで、expert を追加した後の推定使用量が最小の rank に枠を割り当てる。容量と安全余裕を先に制約し、その枠内で層別の校正頻度を用いて選択数を均等化する。校正データがない場合は同じ頻度と仮定する。expert の配置は読み込み時に決まり、router の選択 ID や weight は変更しない。

本体の固定重みは 4,329,651,680 byte、DFly は 424,428,112 byte、folded 重みは 1,056,964,608 byte、射影表は rank ごとに 2,015,232 byte。各 GPU は 32 GiB、別途 0.5 GiB の安全余裕を仮定する。表には作業域、射影表、folded 重みを含む。転送用 pinned host buffer は GPU VRAM には含めない。

| 予約長 | 台数 | 配置 | expert 数 | 推定使用量 GiB |
|---|---:|---|---|---|
| 2Mi | 3 | 調整前の例 | 5000 / 7996 / 7996 | 32.374 / 26.993 / 26.993 |
| 2Mi | 3 | 調整後 | 3917 / 8538 / 8537 | 28.786 / 28.789 / 28.786 |
| 1Mi | 3 | 調整前の例 | 5000 / 7996 / 7996 | 28.179 / 26.993 / 26.993 |
| 1Mi | 3 | 調整後 | 4762 / 8115 / 8115 | 27.390 / 27.387 / 27.387 |
| 2Mi | 4 | 調整前の例 | 4000 / 5664 / 5664 / 5664 | 29.061 / 19.267 / 19.267 / 19.267 |
| 2Mi | 4 | 調整後 | 1783 / 6403 / 6403 / 6403 | 21.716 / 21.715 / 21.715 / 21.715 |
| 1Mi | 4 | 調整前の例 | 4000 / 5664 / 5664 / 5664 | 24.866 / 19.267 / 19.267 / 19.267 |
| 1Mi | 4 | 調整後 | 2733 / 6087 / 6086 / 6086 | 20.668 / 20.669 / 20.665 / 20.665 |

調整前の例も同じ実サイズ、folded 重み、射影表と作業域で計算した。2Mi の 3 台でも expert 配置だけで静的には収まるため、DSA の attention と KV を他 rank へ移す変更は採用しない。仮に層ごとに移す場合、4 stream の BF16 iHC 状態は片道 24,576 byte/token、rank 0 との往復なら 49,152 byte/token を追加する。12 層をそれぞれ往復する配置では最大 589,824 byte/token となり、転送待ちも加わる。隣接層をまとめれば転送回数は減る。実際のリンク性能と peak VRAM の測定は未実施であり、両方を確認してから再検討する。

単体 R9700 で共有 lock を取得し、2Mi の 3 台配置の各 rank 相当 30,908,755,688 / 30,911,762,432 / 30,908,205,056 byte と、4 台配置の 23,317,315,304 / 23,316,764,672 byte を `hipMalloc` で順に確保・解放できた。各試行前の空きは 34,133,245,952 byte。これは単体・逐次の確保確認であり、複数台の同時予約、推論中のピーク、通信の検証ではない。
