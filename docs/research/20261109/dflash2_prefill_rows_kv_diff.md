# DFlash2 prefill の行数による K/V 差

2026-11-09 の調査では、同一の target tap を 8 行ずつ投影した場合と 256 行ずつ
投影した場合の差が、`fc.weight [5120, 25600]` の GEMM で初めて現れた。
8 行は `ExactRowsDot2`、256 行は `WmmaWide` を選択する。256 行側の FC だけを
8 行ずつに変更すると、FC から K/V ring まで全要素が一致した。逆に 8 行側の FC を
`WmmaWide` に固定すると、256 行側と全段階で一致した。したがって、この入力での
不一致は FC の演算経路変更による。各命令内部の丸めは分離していない。

R9700、Qwen3.8-27B EXL3-INT8 target、Qwen3.8-27B-DFlash2 drafter、BF16 K/V、
2048 token の比較では、最終 K の 10,485,760 要素中 125,456 要素、V の同数中
247,965 要素が bit 不一致だった。最大絶対差は K 0.0625、V 0.125。2 ULP を超える
要素も K 15,184 個、V 20,611 個あった。ゼロ近傍や符号変化では ULP 距離が大きく
なり得る。これはこの入力での観察であり、生成品質の一般的な同等性を保証しない。

調査原本は調査時のローカル Git object `00f36aa` の
`docs/research/20261109/dflash2_prefill_rows_kv_diff.md` にある。上記は同記録の
原因と代表的な結果を抜粋したものであり、計測時の一時診断を製品へ含めていない。
