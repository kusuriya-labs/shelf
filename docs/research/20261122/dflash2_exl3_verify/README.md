# Qwen3.8-27B の EXL3 mul24 と DFlash2 固定 8 行 verify

Issue #38 の項目 1・6。開始点は `8d53516f`。Radeon AI PRO R9700（gfx1201）1 台、ROCm 10.2、Release、HIP Graph 有効。モデルは 3.05 bpw と 4 bpw の mul24、drafter は 4 bpw の mul24、KV は BF16。全 GPU 測定で R9700 の UUID を指定し、`/tmp/r9700.lock` を取得した。

4-bit の連続 projection 統合と、17〜64 行の split / occupancy 調整の既存結果を参照した。 [連続 linear の実験](../../20261113/exl3_general/exl3_general.md)・[中間行数の実験](../../20261110/exl3_int8_mid_rows.md)

## 本体と head の差

既存の 3.05 bpw のトレースで、greedy の 25.39 ms は本体の全 GEMM の合計。そのうち単独の 3-bit GEMM 354 回が 24.10 ms を占める。sampled ではそれぞれ 25.72 ms と 24.41 ms。本体全体の trellis は 9,274,654,720 B で、gate/up の 3-bit 128 本と down の 3-bit 64 本で 6,417,285,120 B（69.2%）を占める。head は 6-bit 1 本、953,548,800 B。有効帯域は trellis のバイト数を GEMM 時間で割った値で、入力回転・出力回転の時間は含まない。

同じ N=248320、K=5120、8 行、split=2 にそろえた合成重みで、変更前の 3 / 4 / 6-bit はそれぞれ 407 / 572 / 583 GB/s だった。3-bit は 6-bit の半分の重みバイト数で同数の WMMA と trellis 状態復号を必要とする。さらに同じ 3-bit でも N=17408 の gate/up は約 333 GB/s、N=1024 の K/V は約 121 GB/s。小さい grid と bit あたりの復号コストの両方が効く。head の grid は 31,040 wave、後者の 2 形状は 2,176 / 320 wave。起動単位は 128 thread で、1 wave が出力 16 列を担当する。これらは grid の wave 数であり、実行中の常駐数の計測値ではない。

### 窓抽出の変更

3-bit の 1 lane が使う 8 個の 16-bit 窓は、2 語の中で 37 bit を占める。開始位置は 3、11、19、27 のいずれか。最初の 4 窓と後半の 4 窓の基準をそれぞれ一度そろえると、個々の窓は定数シフトで取り出せる。この変更を 1 WMMA 行タイル（16 行以下）の GEMM に適用した。split、積和順、scale、丸めは従来どおり。

ROCm clang の gfx1201 device assembly による静的な比較。命令数は kernel 全体の該当 opcode 数、occupancy はコンパイラが示す上限（wave/SIMD）。実行時間を命令種別に配分する hardware counter は取得していない。

| bit / 版 | VGPR | occupancy | scratch B/lane | cndmask | alignbit | WMMA |
|---|---:|---:|---:|---:|---:|---:|
| 3 変更前 | 99 | 12 | 0 | 100 | 64 | 8 |
| 3 窓変更後 | 93 | 16 | 0 | 20 | 16 | 8 |
| 4 | 89 | 16 | 0 | 17 | 24 | 8 |
| 6 | 114 | 12 | 0 | 100 | 64 | 8 |

## 採否

* **採用**。3-bit の 1 行タイルの窓抽出。8 行の gate/up と down でそれぞれ約 12 µs 短縮した。
* **棄却**。3-bit の split=4 固定。窓変更版の 8 行 gate/up は split=2 の 87.97 µs から 81.94 µs に短縮したが、BF16 出力 139,264 個中 21 個が変化した。10240 × 5120 は split=1 の 59.45 µs から 53.28 µs に短縮、81,920 個中 17 個が変化。1024 × 5120 は split=5 の 14.38 µs から 15.80 µs に悪化した。3 ペア交互計測。採用版は split の選択を維持する。
* **棄却**。3-bit projection 統合を eager にも適用する案。窓変更済みの版との 3 ペア比較で、greedy の verify は 32.31 → 30.01 ms だったが、sampled は 34.22 → 51.28 ms に悪化した。いずれも同じ生成 ID 列。sampled のトレースでは、verify 中の kernel 間の空白合計が基準版 9.29 ms、無条件統合版 31.11 ms、採用版 9.37 ms。group_rotate 直前の空白の中央値はそれぞれ 4.84 / 105.10 / 4.96 µs。host と driver のどちらが空白を生んだかは切り分けていない。
* **採用**。3-bit projection 統合を graph capture 中の 1〜8 行に限定する。同じ入力の gate/up、QKV/Z、Q/K/V のうち、既存の matcher が連続性、型、workspace、出力領域などを検証できた組を対象とする。projection ごとに `suh` が異なるため、回転結果は個別に計算し、入力回転・GEMM・出力回転を各 1 dispatch にまとめる。

greedy の単独 3-bit GEMM は 354 → 115 回で、3-bit の group GEMM が 117 回。単独の入力回転は 354 → 115 回、単独の BF16 出力回転（f4）は 357 → 99 回。入力回転群全体（融合 producer を含む）は 378 → 256 回、0.79 → 1.03 ms、出力回転群は 378 → 227 回、0.85 → 0.67 ms。入力回転群には従来は別の kernel で実行した演算も含まれる。

greedy では既存の residual / RMSNorm と回転の融合も成立する箇所が増える。sampled は eager の個別 projection を使う。トレース値には profiler の負荷が含まれる。

## 検証と次段

関連 CTest は 67 PASS、失敗 0。2 GPU 必須の optional 5 件（Qwen35 TP execution、MoE TP layer trace / execution、Qwen35 TP E2E、DFlash2 TP E2E）は単一 GPU 隔離のため skip。required に skip はない。GDN の参照テストには Git LFS ポインタの SHA-256 と一致する safetensors 実体を使用した。

Phase 2 で sampled verify の Graph 化を試す際は、同じ 8 行・同じ ID 列で capture 時の projection 統合を計測する。採用版の sampled eager が対照になる。drafter の Graph 化は draft 区間を独立に測る。今回の prefix cache は無効で、prefix capture のページ境界に関する測定値は得ていない。ページ境界の直前・一致・直後で prefix hit と生成 ID を別に検証する。

単体 5 ペアの各 run と、実モデルの各 run の値と ID 照合値を CSV に収録した。 [単体測定](micro.csv)・[実モデル](e2e.csv)
