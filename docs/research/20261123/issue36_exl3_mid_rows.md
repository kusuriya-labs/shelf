# Issue #36: EXL3 projection group の中間行数

## 対象と判断

4 bit projection group は 33〜64 行を MT=2 の複数 row block で実行していた。
33〜48 行は MT=3、49〜64 行は MT=4 として同じ重みの展開回数を減らす。
16 行以下と 65 行以上の選択は変えない。3 bit の Qwen group 経路は Graph capture 中の
16 行以下に限定される。`launch_fused_output` は PLaMo の形状融合用で、現在の kernel は
MT=1 を前提とするため、行数制限だけを緩める変更は行わない。

## projection group の制御比較

R9700 gfx1201、ROCm 10.2、Release。`flock /tmp/r9700.lock` と GPU UUID の指定を使用。
乱数で生成した入力と 2 本の 4 bit 重みを用い、それぞれ N=17408、K=5120、split=4。
合計の重みは約 85 MiB。rotate・group GEMM・出力変換をまとめて hipEvent で計測した。
各実行は 64 回連続実行を 7 組行い、先頭 2 組を除く中央値。実行順は変更前、変更後、
変更後、変更前。各実行で単体 GEMM を組み合わせた参照と BF16 出力を bit 単位で比較した。
これは合成入力であり実モデル全体の速度ではない。

## 単体 GEMM の分割数

同じ GPU と ROCm で `shelf-bench exl3-int8` の 4 bit、重みの循環領域 256 MiB、
64 回/組、5 組中央値を測定した。N=5120、K=17408 で split=12 と 6 を AB/BA 比較。
64 行の total は 181.68 / 182.57 µs に対し 175.65 / 175.24 µs、GEMM 自体は
160.81 / 160.96 µs に対し 160.42 / 161.00 µs、出力変換は約 12.5→8.4 µs だった。
48 行の total は 140.54 / 140.76→136.98 / 136.91 µs。分割数変更の効果は主に
出力変換であり MT=4 の依存鎖の改善ではない。加算順序も変わるため、実モデルの品質と
各形状への影響を検証するまで採用しない。

## 残課題

単体 GEMM の 49〜64 行パイプラインと GDN recurrence の改善は未実装。GDN の既存調査は
[行数と帯域](../20261111/gdn_recurrence_rows.md)を参照。今回の group kernel 比較だけでは
DFlash2 の実モデル速度、greedy ID、KL の改善や不変性を証明しない。

## 実モデルの chain 比較

Qwen3.8-27B EXL3 4 bpw mul24 と EXL3 4 bpw drafter、BF16 KV、draft 7、
greedy、最大 128 token、prefix cache 無効。同時数 2・3・4 ごとに変更前、変更後、
変更後、変更前の順で実行し、各 request の生成 ID は 4 回で一致した。
全 request が稼働する共通区間の tok/s は次のとおり。

| 同時数 | 変更前 2 回 | 変更後 2 回 | 共通区間 |
| ---: | ---: | ---: | ---: |
| 2 | 124.77, 122.10 | 124.61, 124.76 | 約 1.36〜1.39 秒 |
| 3 | 241.41, 241.12 | 241.27, 241.24 | 約 1.23 秒 |
| 4 | 344.77, 345.12 | 342.18, 344.49 | 約 1.10 秒 |

共通区間は短く、到着時刻と batch の偏りを含むため、微小な速度差の根拠にしない。
chain の最大 verify 行数は同時数×8 で、33 行以上の改善実証ではない。
KL の比較は行っていない。

## 実モデルの tree 比較

同じ短い条件で同時数 4、tree budget 10 を AB/BA 比較した。共通区間速度は変更前
265.62 / 267.06 tok/s、変更後 307.00 / 306.13 tok/s だったが、共通区間は
約 1.3〜1.5 秒である。変更前 2 反復同士でも request 1 の生成 ID が 36 番目から分岐し、
変更後の 2 反復は変更前の 2 回目と一致した。ほかの 3 request は全反復で一致した。
生成軌跡が同一でないため、速度差を kernel 変更の効果と判断できない。対象行数での
安定した実モデル速度と品質の比較は引き続き必要である。

変更後の別途実行した phase trace では、4 request・40 行の tree verify が 17 回、
4 request・36 行が 1 回観測された。この trace は通常速度の比較とは別実行である。

## 受入テスト

ROCm 10.2 / gfx1201 の Release build で全ターゲットをビルド後、required acceptance は
232 件成功、失敗・skip とも 0 件。作業環境に Git LFS がなく fixture がポインターだったため、
必要な実体を取得して SHA-256 を照合してから実行した。

単一 request の DFlash2 chain は同条件で 128 token、AB/BA の順に実行し、
変更前 57.97 / 57.82、変更後 58.09 / 57.96 tok/s。生成 ID は 4 反復で一致した。
これは投機ありの確認であり、投機なし decode 単独の速度比較ではない。
