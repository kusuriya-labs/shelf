# EXL3 W16A16 の初期実装

## 目的

ExLlamaV3 の EXL3 checkpoint を Shelf で読み、trellis を保持したまま 16-bit の
weight / activation で linear を実行する経路を追加する。INT8 への再構成は行わない。

## 参照

- format と CPU 参照: `references/exllamav3/tests/testlib/trellis.py`
- codebook: `references/exllamav3/exllamav3_ext/quant/codebook.cuh`
- RDNA の実行経路: `references/exllamav3/exllamav3_ext/rocm/quant/`
- 旧 INT8 実装（比較のみ）: `shelf_old` の未接続コミット `84592f70`

## 実装した contract

- `QuantizedEncoding::Exl3`、`QuantSpecId::EXL3_W16A16_V1`、
  `ComputeSpecId::EXL3_W16A16_F32_BF16`、`KernelId::LINEAR_EXL3_W16A16`。
- payload は trellis（I16）/ suh（F16）/ svh（F16）/ marker（I32）の 4 plane。
- `k` と `n` は 128 の倍数、`k_padded == k`。
- コードブックは marker 名で mcg / mul1 を選ぶ。整数 rate 1..8 と
  mul1 の 1.5 / 2.5 / 3.5 を受理する。
- kernel は 16 行 × 128 列の block で、trellis を 128 K ごとに復号しながら
  F16 WMMA（F32 累算）する。入力回転と出力回転は同じ kernel 内で行う。
- TP partition、MoE routed expert、DFlash2 drafter、vocab-parallel LM head は
  EXL3 を受理しない。

## 検証

- CPU codec: `test_exl3_codec`。
  - 3inst / mcg / mul1 の全 65,536 状態を fp16 bits の CRC32 で参照と比較。
  - 整数 rate 2..8 と half 1.5 / 2.5 / 3.5 の乱数 tile を参照と比較。
  - 128×128 の dequant を参照のサンプル値と比較。
- GPU helper: `test_exl3_linear`。
  - codebook 全状態と ring window を device 実装と CPU 実装で比較。
  - FWHT を CPU の正規化 Hadamard と比較。
- GPU linear: `test_exl3_linear`。
  - rows 1 / 3 / 5 / 16 / 17、K=128 / 256、N=128 / 256 / 384。
  - mcg 4/6 bpw、mul1 3.5 half、mul1 7 bpw。
  - CPU dequant + FP64 matmul を参照に、max_abs <= 2e-2 または
    max_rel <= 3e-3 で一致。
- checkpoint: `test_hf_manifest` と `test_weight_load`。
  - HF の `quant_method == "exl3"` から manifest を合成し、4 plane を解決する。
  - GPU へ trellis / suh / svh / marker がバイト一致で転送される。
  - `make_weight_slot` が 4 plane と rate / codebook を保持する。
- `test_weight_slot_validation` で EXL3 slot の受理・拒否を固定した。

## 実 checkpoint

`models/Qwen3.8-27B-exl3`（`model_type: qwen3_5`、4 bpw、lm_head 6 bpw、mul1）で
`shelf-compute` を通した。

- 未量子化の `linear_attn.in_proj_a/b` は F16 で保存されているため、HF 合成時に
  BF16 へ widen する経路を追加した。変換は host の staging で行い、manifest の
  payload dtype は BF16 のままにする。
- `The capital of France is`（ids 760, 6511, 314, 9338, 369）を greedy で 8 token
  生成し、` Paris.\nThe capital of Germany is` を得た。

## 未実施

- rows == 1 専用の GEMV。現状は 16 行 block をそのまま使う。
- 性能測定と最適化。weight は block ごとに復号するため、prefill では行 tile を
  広げた再利用が必要になる可能性がある。
- correctness mode（`SHELF_QWEN35_KERNEL_MODE=correctness`）の EXL3 経路。
