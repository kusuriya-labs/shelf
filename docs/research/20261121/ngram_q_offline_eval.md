# n-gram table の CPU オフライン量子化比較

2026-11-21。**未完了**。実行できた比較を記録する。Step 1 の完了判定ではない。

## 条件

CPU は AMD Ryzen Threadripper PRO 3995WX、64 core / 128 thread。GPU は使用していない。実験コードと中間結果は `/tmp/ngram_q_step1/`。Hy4 は指定された BF16 原本と現行 FP8 artifact、Qwen は `pilot.py` に記載の BF16 原本を使用した。

Hy4 は layer 1 / 11 / 21 / 31 の各 16 head、Qwen は layer 1 の 16 head。Qwen は各 head に含まれる shard 3, 11, …, 123 のみから抽出したため、head 全域の代表性は未確認。各 head は乱数で 3,072 行を非復元抽出し、1,024 行を codebook 学習、2,048 行を held-out 評価に使う。各方式は同一行を使用し、同じ行番号の各 head を連結して 2,048 組を構成する。mix43 は Bigram に 4-bit、Trigram に 3-bit を用いる。自然言語の n-gram 頻度を反映した標本ではない。

表の `mean / p95 / p99` は relative L2 の百分率。全体と次数別は実際の誤差標本をプールして計算した。Hy4 の投影は BF16 重みの head RMSNorm（epsilon 1e-5）後に連結し、bias 込みで各 key と value に通した。Qwen は連結後に BF16 重みの key/value を通した。参照は同じ BF16 行の投影結果。FP8 は指定された現行 artifact の実際の E4M3 code と BF16 row scale を読み、INT6 は W32、FP16 scale、-32..31 の現行形式で再量子化した。

Lloyd–Max は head ごとに学習した codebook と行ごとの誤差適合 FP16 scale を使用した。均等 4-bit は -7..7 と absmax FP16 scale。試作 TCQ は 16 状態の shift register、状態ごとの固定再構成値、Viterbi、各段の FP16 scale を使う。codebook は正規分布を意識した固定値の試作で、最適化済み Gaussian codebook ではない。開始状態の格納などの実用 codec 仕様は未完成。sign は各段の残差平均絶対値を FP16 scale とする。

bit/elem は payload の理論値で、行 padding、codebook、TCQ の初期状態などは含まない。Hy4 / Qwen の順に、FP8 は 8.167 / —、INT6 W32 は — / 6.500、Lloyd 4/3/2 は 4.167/3.167/2.167 と 4.100/3.100/2.100、TCQ・sign は各段 1.167 と 1.100、mix43 は 3.667 と 3.600 である。

追加した `lloyd5` は既存の Lloyd と同じ head 単位の学習と誤差適合 row scale、`uniform5` は -15..15 と absmax row scale。`lloyd4_w32` は 32 要素ごとの absmax 正規化標本から head 共有 codebook を学習し、group ごとに誤差適合 FP16 scale を使う。いずれも E1 / E2 と同一標本・同一射影条件。理論 payload は 6.60 億行 / 3.20 億行、1 行 96 / 160 要素とし、codebook や付帯情報は含めない。

### 追加: 学習した 16-state TCQ の比較

C++ `-O3 -march=native -fopenmp` の 16-state shift-register trellis、各状態の再構成値、Viterbi を使用した。各段は残差を入力とし、行ごとに scale を 3 回反復適合した後 FP16 に丸める。codebook は各段で Viterbi の経路割当と状態別平均更新を 30 回反復した局所解で、Gaussian 版は独立正規乱数 8,192 行 × 160 要素、実データ版は Hy4 layer 1 と Qwen layer 1 の各 head 0〜7 の学習用行それぞれ 8,192 行を行 RMS で正規化して学習した。各段の学習対象は前段までの再構成残差。実データ版の評価行は学習に使っていないが、他の層にも同じ codebook を使う。Gaussian と実データの双方で 1 回の初期化のみであり、最適性の保証はない。球面 codebook や QTIP / GateRQ の全設計を実装したものではない。

### Hy4 の scale を含む順位付けの代用実験

上記の同じ標準正規 query と 2,048 組を使用し、各組を sign1 から sign2 へ更新する対象として順位付けした。sign1 の推定 gate を `α_m`、実 `unified_per_hc_scales` を `s_mj` とし、4 stream の `Σ_m α_m²` と `Σ_m mean_j((α_m + s_mj)²)` を比較する。前者は各 stream の value が同一ベクトルであるため mean による定数倍を省略した。上位 25% または 50% の組だけ sign2 に変更し、4 stream の `round_bf16(round_bf16(value * gate) + round_bf16(value * scale))` の BF16 原本との差の二乗和を算出した。表は全組 sign1 の二乗誤差を基準にした減少率 %。oracle は各組の実際の誤差減少を使う上限、ランダムは一様選択の期待値。

### 追加: 仮形式による CPU 復号と量子化の予備測定

`g++ -O3 -march=native`、単一 thread。4,096 行を反復し、packed code の読み出し、LUT、FP16 scale 読み出し、FP32 出力を含めた。TCQ は各段の 1-bit stream と開始状態を持つ仮形式を使った。測定は cache 内の連続行で、FP8 の scale は仮の FP16、例外 code は 0 に置換しており、現行 FP8 artifact の BF16 scale や例外処理とは異なる。INT6 の符号配置も仮形式であり、各方式の production codec の実仕様・SIMD 最適化やランダム lookup を検証した値ではない。したがって E6 は引き続き未完了。

## 判断と未完了項目

- Lloyd 5-bit の value 射影誤差は Hy4 4.603%、Qwen 4.831%。4-bit W32 はそれぞれ 7.299%、7.154% で、4-bit row scale の 8.396%、8.589% を下回る。いずれも現行基準より誤差は大きく、採用可否は未判定。
- 4-bit / 3-bit の Bigram / Trigram 混合は候補に残すが、今回の独立連結サンプルだけでは実 workload の品質差を実証できない。混合そのものの行・投影結果は `mix43` として E1 / E2 に示す。
- 学習した 16-state TCQ 3 段は sign3 より改善するが 3-bit Lloyd–Max に届かず、現時点の第一候補にはしない。局所最適化した 1 設計だけで球面 shaping や他の TCQ 全般を否定できない。
- Hy4 の実 query 分布と BF16 計算の完全一致、TCQ による重要度順位付け、Qwen gate の中間 BF16 丸めを含む再現性、Qwen 全 head の語彙全域からの抽出、実 codec の単一行復号、64 core での量子化込み全表変換時間は未測定。Qwen の shard 内サンプルと独立連結は実 workload を代表するとは限らない。
- Step 2 に進める最終候補の確定には、上記の未測定項目と end-to-end 品質・実 codec のコスト検証が必要。
