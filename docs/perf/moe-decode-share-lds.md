# grouped EXL3 mul24 の LDS 共有と活性前処理

2026-11-08、R9700 gfx1201 1 枚、ROCm 7.14、Release。`bench_exl3_int8_grouped`、hidden 2560、intermediate 640、512 expert、top-10、合成重みと入力、3 回 warmup と 20 回平均。各 benchmark は `/tmp/r9700.lock` を保持して単独実行した。表は gate と down の GPU 時間の和、単位 ms。基準の FP16 / INT8、A の LDS 共有 FP16 / INT8、B の INT8 前処理、A+B の INT8 前処理と LDS、C の自動選択を示す。各表の行は独立した一連の測定で、外部条件の変動を含む。変更前 fc4f652 の測定は [前回の記録](moe-decode-share-reference.md) にある。

benchmark の候補切り替えは `SHELF_BENCH_MUL24_LDS=1` と `SHELF_BENCH_MUL24_PRE=1`、C は `SHELF_BENCH_MUL24_AUTO=1`。`--bits 3` または `--bits 4`、偏りありは `--skew`、expert 1 個は `--single-expert`、単独 token 数は `--tokens` を指定する。`--reverse` は基準と候補の測定順を入れ替える。各回の呼び出しは次の形で、候補の環境変数と引数を追加した。

```sh
flock /tmp/r9700.lock env ROCR_VISIBLE_DEVICES=GPU-a8e9ddefa2d60f55 \
  LD_LIBRARY_PATH=/home/homelab1/coding-local/sLLM/.local-artifacts/phaseshift-draft-vocab/toolchain/root/usr/lib/llvm-23/lib:$LD_LIBRARY_PATH \
  build-gfx1201/tests/bench_exl3_int8_grouped --bits 3 --iters 20
```

A は 48 行分の FP32 部分和と 128×128 の INT8 復号重みを LDS に保持し、16 行 tile ごとに同じ復号重みを読み直す。1 wave の累積器は 16 行 tile 一つ分のみ。B は group row と 128 要素単位の INT8 コードと scale を先に書き、GEMM はそれを読む。C は opt-in であり、測定済みの 3 / 4 bit、256 token 以上、2560×640 または 640×2560 のみ B の INT8 を選び、その他は従来の FP16 を選ぶ。C の閾値は expert 個別の行数ではなくバッチの token 数であり、各 expert に最適な選択を保証しない。既定は従来 FP16 のまま。

## 内訳とリソース

2048 token、3 bit、一様の `rocprofv3` kernel trace では、B の回転・量子化が gate 0.311 ms、down 0.105 ms、GEMM がそれぞれ 2.410 ms、1.882 ms。A+B は回転・量子化が gate 0.298 ms、down 0.105 ms、GEMM がそれぞれ 4.849 ms、4.796 ms。3 回の warmup を除く各 20 回の平均で、profiler のオーバーヘッドを含む。`--tokens 2048` では乱数の消費順が表と異なるため、生成された routing も異なる。

`--tokens 2048` で実行順を基準→候補と候補→基準に交互に変えた 5 回の測定では、gate+down の中央値は従来 FP16 が 5.845 ms、C が 4.674 ms。各実行は 20 回平均で、範囲は従来 5.836〜5.867 ms、C 4.660〜4.675 ms。実モデルの速度ではない。

3 bit の code object と `hipModuleOccupancyMaxActiveBlocksPerMultiprocessor` の結果。LDS は byte、VGPR は wave あたり、同時 block 数は HIP が返した上限。全て wave32、256 thread、private segment と VGPR / SGPR spill は 0 byte / 0 個。

| kernel | LDS | VGPR | SGPR | 同時 block 数 |
|---|---:|---:|---:|---:|
| 従来 FP16、N tile 1 | 16896 | 130 | 53 | 3 |
| 従来 FP16、N tile 2 | 25088 | 132 | 53 | 2 |
| A FP16 | 54016 | 85 | 54 | 1 |
| A INT8 | 48064 | 91 | 56 | 1 |
| A+B INT8 | 48064 | 64 | 42 | 1 |
| B INT8、N tile 1 | 12928 | 89 | 40 | 5 |
| B INT8、N tile 2 | 21120 | 111 | 40 | 3 |
| 回転・量子化 | 0 | 29 | 30 | 8 |

A は復号を 48 行で使い回す一方、LDS の重み・部分和の読み書きと同時 block 数 1 によって処理時間が増えたと考えられる。計測はそれぞれの寄与を個別に分離していない。B は回転を n ブロックごとに繰り返さず、GEMM の VGPR 数も小さくなる。profiler の時間と occupancy はこの説明を支持するが、個別の因果関係を確定するものではない。

作業領域は `k + 4 * (k / 128)` byte / group row。実行行 20480 行だけなら gate 51.56 MiB、down 12.89 MiB。実際は expert ごとの 16 行境界の余りも必要で、512 expert、2048 token、top-10 の安全な上限 28160 行では gate 70.90 MiB、down 17.72 MiB。MoE scratch の plan 配列の後ろに両者の最大値を確保して再利用する。

## 実験の指定と限界

- `SHELF_EXL3_MUL24_AUTO=1` は C を有効にし、条件内では INT8 活性を使うため従来 FP16 と丸めが異なる。条件外は FP16。program の構築時から設定する。
- `SHELF_EXL3_MUL24_PRE=1 SHELF_EXL3_INT8_MOE=1` は B を強制する。`SHELF_EXL3_MUL24_LDS=1` は A を強制し、B と組み合わせられる。いずれも実験用。
- ベンチマークは合成入力による個別 projection の時間で、実モデル全体、複数 GPU、融合 gate/up の 1280 出力列は未検証。
- expert ごとに A / B / 従来を切り替える dispatch は未実装。C はバッチ単位の保守的な条件で、混在する expert の行数ごとに最速を選んではいない。
